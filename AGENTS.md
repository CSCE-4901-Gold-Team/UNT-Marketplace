# UNT Marketplace - Agent Instructions

## Stack
Next.js 15 App Router, React 19, TypeScript, PostgreSQL, Prisma, better-auth, Playwright, Tailwind CSS v4. Package manager is **npm**.

## Commands
- `npm run dev` &mdash; dev server with Turbopack (localhost:3000)
- `npm run build` &mdash; build with Turbopack
- `npm run vercel-build` &mdash; production build (`prisma migrate deploy && next build`)
- `npm run lint` &mdash; run ESLint
- `npm run seed` &mdash; seed database with `tsx`
- `npx playwright test` &mdash; run E2E tests
- `npx playwright test tests/auth/login.spec.ts` &mdash; run a single test file

## Setup
1. Copy `.env.example` to `.env` and fill in all variables
2. `npm install` &mdash; triggers `prisma generate` via `postinstall`
3. Run migrations: `npx prisma migrate deploy`
4. Seed database: `npm run seed`

## Environment Variables (from `.env.example`)
`DATABASE_URL` (PostgreSQL), `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `APP_URL`, `SENDGRID_API_KEY`, `SENDGRID_FROM_EMAIL`, `SENDGRID_FROM_NAME`.

## TypeScript Path Alias
`@/*` resolves to **both** `./src/*` and `./generated/*`. The `generated/` directory contains Prisma types regenerated by `prisma generate`.

## Database
- PostgreSQL only. Prisma uses `fullTextSearchPostgres` preview feature (the `{search: ...}` filter syntax requires Postgres).
- Prisma client is a singleton (`src/lib/prisma.ts`) to avoid connection pool exhaustion in dev.
- Import prisma from `@/lib/prisma`, NOT directly from `@prisma/client`.
- Enums are imported as `import { $Enums } from "@prisma/client"` then aliased (e.g., `import ListingStatus = $Enums.ListingStatus`).

## Auth
- better-auth with Prisma adapter. Auth instance exported from `src/lib/auth.ts`.
- Email verification required on sign-up. UNT email domains enforced (`my.unt.edu`, `unt.edu`).
- Session expires in 7 days.
- Seed users: `test.user@my.unt.edu` / `rootroot`, `admin@my.unt.edu` / `testtest` (ADMIN).

## Architecture
- **`src/actions/`** &mdash; Server actions (`"use server"`) for all business logic (listings, auth, chat, admin, etc.)
- **`src/app/api/`** &mdash; API routes organized by feature: `auth/`, `cron/`, `listing/`, `profile/`, `saved-queries/`, `user-role/`
- **`src/components/`** &mdash; UI components: `admin/`, `features/`, `layout/`, `profile/`, `ui/`, `suspense/`
- **`src/lib/`** &mdash; Core services: `auth.ts`, `prisma.ts`, `email-service.ts`, `profanity-filter.ts`, `toast-service.ts`, `image-adapter.ts`
- **`src/models/`**, **`src/types/`**, **`src/schemas/`** &mdash; Data models, TypeScript types, Zod validation schemas
- **`src/utils/`** &mdash; Helpers: `ListingUtils.ts`, `StatusEnforcer.ts`, `ZodValidators.ts`, `DateHelper.ts`, `ErrorHelper.ts`, `ImageUtils.ts`

## Next.js Config Quirks
- `images.unoptimized: true` &mdash; no image optimization; images stored as static file paths
- `serverActions.bodySizeLimit: '10mb'` &mdash; raised for base64 image uploads
- `eslint.ignoreDuringBuilds: true` &mdash; ESLint errors won't block production builds
- ESLint config (`eslint.config.mjs`) ignores `generated/**`

## Image Handling
All image upload, compression, storage, and deletion goes through the `imageAdapter` in `src/lib/image-adapter.ts`. Images are compressed with `sharp` and saved as static files in `public/uploads/`. The DB stores relative file paths, not base64. See `docs/image-adapter.md` for full details.

## E2E Tests (Playwright)
- Config in `playwright.config.ts`. Tests in `tests/`.
- **Dev server must be running manually** before tests (the `webServer` block is commented out).
- `baseURL` comes from `APP_URL` env variable.
- Runs against Chromium and Firefox (4 workers max &mdash; more overloads the dev server).
- 15s expect timeout. Retries only on CI.
- See `docs/playwright-testing.md` for login helper, category dropdown interaction, and common pitfalls.
- See `tests/AGENTS.md` for test-writing constraints and patterns.

## Form Submission Patterns
- The create/edit listing form disables the submit button while categories are loading (`isLoadingCategories` state).
- Always wait for the category input (`input[id="categoryIds"]`) to be **enabled** before selecting a category.
- Always wait for the submit button to be **not disabled** before clicking it.
- After form submission, wait for redirect with a timeout &mdash; don't use `page.waitForLoadState("networkidle")` (hangs due to Next.js HMR).
- The delete confirmation is a two-step UI flow: click "Delete Listing" button, wait for confirmation dialog to appear, then click "Confirm Delete".

## Deployment
- Deployed on Vercel. Production build uses `vercel-build` script.
- Cron job: `GET /api/cron/process-saved-queries` runs daily at 9:00 UTC (defined in `vercel.json`).

## Git Workflow
- PRs to `main` are blocked unless sourced from `staging` (enforced by `.github/workflows/enforce-staging-pr.yml`).

## User Roles
`STUDENT` (default), `FACULTY`, `ADMIN`. Faculty/Admin can see `isProfessorOnly` listings. Unapproved students have listings created as `DRAFT`.

## Listing Statuses
`AVAILABLE`, `DRAFT`, `SOLD`, `ARCHIVED`.

## Plans
- Store all plan documents in `.opencode/plans/` as `.md` files (e.g., `.opencode/plans/microphone-fix-plan.md`).
- Plans are used for issue assessments, fix plans, feature design documents, and other structured analysis. They are not committed to the repository.
- When asked to generate a plan, inspect the relevant code first, then write a plan document with: (1) root cause analysis with file:line references, (2) recommended fixes with priority, (3) implementation order, (4) testing plan.

## Workflow Constraints
- **No bypassing the frontend UI** &mdash; tests must interact with the application through the UI as a real user would.
- **Seed data is allowed** &mdash; use `tests/helpers/test-data.ts` to seed entities for tests, but always clean them up in a `finally` block.
- **Validate tests as you go** &mdash; run tests incrementally after each change, not just at the end.
- **Playwright is installed and the dev server runs at `http://169.254.83.107:3000/`** (check `APP_URL` in `.env`).
